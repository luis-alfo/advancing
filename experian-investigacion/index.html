Experian · Consumer Credit Profile API

Documento de investigación técnica — endpoints, autenticación y ejemplos de llamadas REST.

Mercado: US REST / JSON OAuth 2.0 Datos regulados (FCRA)

Fecha: 2026-05-27 · Producto: Consumer Credit Profile · Operación principal: CreditReports

1. Resumen ejecutivo

La Consumer Credit Profile API de Experian permite obtener, en tiempo real, el informe de crédito de un consumidor de Estados Unidos a partir de sus datos personales (nombre, dirección, SSN, fecha de nacimiento). Devuelve un JSON con líneas de crédito (tradelines), registros públicos, consultas previas (inquiries), alertas de fraude y modelos de score (FICO, VantageScore, etc.).

Lo esencial en 4 puntos:
  • Auth: OAuth 2.0 (token Bearer válido 30 min) contra /oauth2/v1/token.
  • Llamada: POST /consumerservices/credit-profile/v2/credit-report con el PII en el body.
  • Sandbox: autoservicio con datos de prueba estáticos; producción requiere contrato.
  • Regulación: sujeta a la FCRA — necesitas un permissible purpose y un subscriber code.

2. Qué es y casos de uso

Es un servicio de credit bureau orientado a decisiones de riesgo. Casos típicos:

  • Originación de crédito / préstamos: evaluar solvencia antes de aprobar.
  • Onboarding y verificación de identidad (combinado con Precise ID / KBA).
  • Pre-aprobaciones y account review.
  • Screening de inquilinos (con renterRiskScore).

Experian agrupa varios servicios relacionados bajo el mismo portal: informes de crédito de consumidor, Precise ID (fraude/identidad), KIQ/KBA (preguntas de conocimiento) e Intelliscore+ (crédito de empresas).

3. Requisitos de acceso

  1. Crear una cuenta en el Experian Global Developer Portal y verificar el email.
  2. En My Apps → Add New App, registrar una aplicación y seleccionar el producto Consumer Credit Profile. Esto genera tu client_id y client_secret.
  3. Probar contra el sandbox con datos de prueba (autoservicio).
  4. Para UAT y producción: suscripción comercial + verificación manual + asignación de un subscriberCode.
Importante: el sandbox es abierto para experimentar, pero el acceso a datos reales está controlado contractualmente. No es una API pública de autoservicio para producción.

4. Autenticación — OAuth 2.0

Flujo tipo password / two-legged. Se obtiene un access_token (JWT Bearer) que se envía en cada llamada posterior.

4.1 Obtener el token

POSThttps://sandbox-us-api.experian.com/oauth2/v1/token

curl -X POST https://sandbox-us-api.experian.com/oauth2/v1/token \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  -d '{
    "client_id":     "TU_CLIENT_ID",
    "client_secret": "TU_CLIENT_SECRET",
    "username":      "tu_usuario_portal",
    "password":      "tu_password_portal"
  }'

4.2 Respuesta del token

{
  "issued_at":     "1716800000000",
  "expires_in":    "1800",           // 30 minutos
  "token_type":    "Bearer",
  "refresh_token": "<refresh_jwt>",     // válido 24 h
  "access_token":  "<access_jwt>"
}
CampoDescripción
access_tokenJWT Bearer. Se usa en Authorization: Bearer …. Vence en 30 min.
refresh_tokenPermite renovar el access token sin re-enviar credenciales. Vence en 24 h.
expires_inSegundos hasta expiración (1800).

7. Estructura del response

El response es un JSON con múltiples secciones. Esquema simplificado:

{
  "creditProfile": [{
    "riskModel": [{                // scores: FICO, VantageScore...
      "modelIndicator": "V4",
      "score": "0712",
      "scoreFactors": [ { "importance": "1", "code": "..." } ]
    }],
    "tradeline": [{               // cuentas de crédito
      "subscriberName": "CAPITAL ONE",
      "accountType": "07",
      "balanceAmount": "001500",
      "openDate": "01012020",
      "status": "11"
    }],
    "inquiry": [ ... ],            // consultas previas
    "publicRecord": [ ... ],       // quiebras, embargos...
    "statement": [ ... ],          // declaraciones del consumidor
    "fraudShield": [ ... ],        // indicadores de fraude
    "informationalMessage": [ ... ],
    "summaries": [ ... ]            // resúmenes agregados
  }]
}
SecciónContenido
riskModelScore(s) y factores de riesgo asociados.
tradelineCuentas: tipo, saldo, límite, historial de pagos, fechas, estado.
inquiryConsultas de crédito previas (hard/soft).
publicRecordRegistros públicos negativos (quiebras, gravámenes).
fraudShieldAlertas de fraude e inconsistencias.
summariesMétricas agregadas (nº de cuentas, deuda total, etc.).

Opcionalmente, el response del paso inicial devuelve un RequestID que permite recuperar el informe en PDF mediante un endpoint secundario (custom-credit-report/pdf/{requestId}).

8. Sandbox y datos de prueba

El sandbox responde con datos estáticos: ciertas combinaciones de PII de prueba devuelven informes predefinidos. No se consulta crédito real.

Ejemplo de identidad de prueba habitual en sandbox:

firstName: ASAD          lastName: YCSWL
ssn:       666455730     // SSN ficticio (rango 666-** reservado para test)
street1:   9817 LOOP BLVD APT G
city:      CALIFORNIA CITY   state: CA   zip: 935051352

Los valores exactos de prueba aparecen en la documentación del producto tras iniciar sesión en el portal. Cada producto tiene su propio set de datos de prueba.

9. Errores y límites

CódigoSignificado típico
401 UnauthorizedToken ausente, inválido o expirado (recuerda: 30 min).
400 Bad RequestPII incompleto o formato inválido (faltan state/zip, SSN mal formado…).
403 ForbiddensubscriberCode o permissiblePurpose no autorizado para el producto.
429 Too Many RequestsRate limiting.
5xxError del servidor; reintentar con backoff.

Las respuestas de error incluyen un cuerpo JSON con errors[] describiendo el problema. El token caduca a los 30 min: implementa renovación con refresh_token.

10. Cumplimiento — FCRA

Crítico: consultar el crédito de una persona en EE. UU. está regulado por la Fair Credit Reporting Act (FCRA). No puedes hacerlo sin base legal.
  • Permissible purpose: debes declarar un propósito legítimo (permissiblePurpose.type): solicitud de crédito, revisión de cuenta, empleo (con consentimiento), alquiler, etc.
  • Consentimiento: en la mayoría de casos necesitas autorización explícita del consumidor.
  • Subscriber agreement: Experian exige un contrato y, a menudo, una inspección física del negocio antes de habilitar producción.
  • Datos sensibles (SSN/PII): obligaciones de cifrado en tránsito y reposo, minimización, retención limitada y auditoría.

11. Encaje con este proyecto

Este repositorio (conciliacion-bancaria) trata reconciliación de movimientos bancarios, aparentemente en contexto europeo (EUR). La Consumer Credit Profile API es un producto US-céntrico de bureau de crédito.

Preguntas a resolver antes de integrar:

  • ¿El caso de uso es de consumidores estadounidenses? Si el negocio es en España/UE, probablemente quieras un bureau europeo (Experian España, Equifax, ASNEF/Experian, etc.) en lugar de este producto US.
  • ¿Hay un permissible purpose y consentimiento claros?
  • ¿Existe presupuesto/contrato? Producción no es autoservicio.

Para una prueba de concepto, el sandbox es gratuito y suficiente para validar la integración técnica (OAuth + llamada al endpoint) sin datos reales.
